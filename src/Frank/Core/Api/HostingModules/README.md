# HostingModules

The **HostingModules** subsystem provides a modular, extensible hosting pipeline
for the Frank.Core API.  
It allows independent hosting modules to contribute configuration overrides,
activate conditionally based on environment, and participate in a deterministic
startup sequence.

This folder contains the infrastructure that evaluates hosting modules,
merges their configuration contributions, and injects them into the ASP.NET Core
configuration system.

---

---

## HostingConfigurationProvider

`HostingConfigurationProvider` is a lightweight configuration provider that
injects a predefined set of key/value pairs into the ASP.NET Core configuration
pipeline.

### Responsibilities

- Loads configuration values supplied by hosting modules.
- Overrides earlier configuration sources (but may be overridden by later ones).
- Integrates seamlessly with `IConfigurationBuilder`.

### Typical usage

Created automatically by `HostingOverridesConfigurationSource`.

---

## HostingOverridesConfigurationSource

`HostingOverridesConfigurationSource` is the configuration source responsible for
producing a `HostingConfigurationProvider`.

### Responsibilities

- Stores configuration overrides generated by hosting modules.
- Builds a provider that injects those overrides into the configuration system.
- Allows hosting modules to contribute configuration without modifying
  appsettings.json or environment variables.

### Typical usage

Added to the configuration pipeline by `HostingEngine`:

```csharp
builder.Configuration.Add(new HostingOverridesConfigurationSource(overrides));
```

---

## HostingEngine

`HostingEngine` is the orchestrator for hosting modules.  
It evaluates modules in a deterministic order, checks whether they are active,
retrieves their configuration overrides, and merges them into the hosting
environment.

### Responsibilities

- Orders hosting modules using `HostingModuleAttribute.Order`.
- Evaluates module activation via `IHostingModule.IsActive`.
- Retrieves configuration overrides via `GetConfigurationOverridesAsync`.
- Merges overrides (later modules win).
- Injects merged overrides into the configuration pipeline.

### Why this matters

Hosting modules allow the platform to:

- enable/disable features based on environment  
- inject configuration dynamically  
- override settings from external systems  
- participate in startup without modifying Program.cs  

The hosting engine ensures these modules run predictably and safely.

### Typical usage

```csharp
var engine = new HostingEngine(modules);
await engine.ApplyHostingEnvironmentConfigurationAsync(builder);
```

## How HostingModules Fit Into the Architecture

Hosting modules are part of the platform bootstrap layer.  
They allow the system to adapt its configuration based on:

- environment (Development, Staging, Production)
- deployment context (local, container, cloud)
- external systems (secrets managers, orchestrators)
- runtime conditions (feature flags, platform metadata)

The HostingModules subsystem ensures:

- modules are evaluated in a deterministic order  
- inactive modules are skipped  
- configuration overrides are merged safely  
- hosting logic remains modular and testable  

---

## Typical Flow

1. **Modules are discovered and instantiated**  
   (usually via DI or orchestrator).

2. **HostingEngine orders modules**  
   using `HostingModuleAttribute.Order`.

3. **HostingEngine evaluates each module**  
   - `IsActive(builder)` determines whether the module applies.  
   - `GetConfigurationOverridesAsync(builder)` returns key/value overrides.

4. **Overrides are merged**  
   Later modules override earlier ones.

5. **Merged overrides are injected**  
   via `HostingOverridesConfigurationSource`.

6. **ASP.NET Core builds final configuration**  
   including hosting module contributions.

---

## Design Principles

- **Modular hosting**  
  Each hosting module is independent and self-contained.

- **Deterministic ordering**  
  `HostingModuleAttribute.Order` defines execution order.

- **Environment-aware activation**  
  Modules decide whether they apply to the current hosting environment.

- **Safe configuration merging**  
  Later modules override earlier ones.

- **Zero boilerplate**  
  Modules contribute configuration without modifying Program.cs.

---

## Notes

- Hosting modules should be lightweight and deterministic.
- Configuration overrides should use standard key naming conventions.
- The hosting engine logs module activity for debugging and transparency.
- This subsystem is designed for future expansion (e.g., cloud providers, secrets managers, feature flag systems).
